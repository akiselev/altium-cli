# PCB Primitive Rendering

## Location

`crates/altium-format/src/render/pcb.rs`

## Entry Point

```rust
pub(crate) fn draw_pcb_primitive(prim: &PcbPrimitive, canvas: &mut dyn AltiumCanvas)
```

Called by:
- `PcbLib::render_footprint()` → `PcbFootprint::render()` — iterates all primitives
  in the footprint

Unlike schematic rendering, PCB rendering does not take a font table parameter.
Font information is embedded directly in each `PcbText` primitive.

## Dispatch Table

| PcbPrimitive variant | Canvas calls | Notes |
|---|---|---|
| `Track` | `draw_line(start, end, pen(BLACK, width))` | Track width becomes pen width |
| `Arc` | `draw_arc(center, radius, radius, start_angle, end_angle, pen(BLACK, width))` | Circular only (rx == ry) |
| `Via` | `draw_ellipse(loc, outer_r, outer_r, annular_pen)` + `draw_ellipse(loc, inner_r, inner_r, hole_pen, hole_brush)` | See Via geometry below |
| `Pad` | Shape-dependent dispatch | See Pad shapes below |
| `Fill` | `push_transform(Rotate)` + `draw_rect(corner1, corner2, pen, brush)` + `pop_transform` | Rotation about corner1 |
| `Region` | `draw_polygon(outline, pen, brush)` | Filled outline polygon |
| `Text` | `draw_text(text, location, rotation, font, pen(BLACK, stroke_width))` | Font from primitive fields |
| `ComponentBody` | `draw_polygon(outline, pen, None)` | Outline only, no fill |

## Color Handling

**Current status**: All PCB primitives render in black (`Color::BLACK`).

Altium's PCB renderer is fundamentally layer-aware — each primitive's color comes from
the layer color configuration, not from the primitive itself. A `Track` on `TopLayer` would
be red, on `BottomLayer` blue, etc. The layer color palette is project-configurable.

Our renderer ignores layer assignments and uses black uniformly. This is adequate for
single-footprint rendering but will need layer color support for full PcbDoc rendering.

## Geometry Details

### Via Rendering

A via is rendered as two concentric circles:

1. **Outer ring** (annular ring):
   - Radius: `diameter / 2`
   - Pen width: `outer_r - inner_r` (annular ring thickness)
   - No fill (stroke-only circle)

2. **Inner hole** (drill):
   - Radius: `hole_size / 2`
   - Pen width: 0 (hairline)
   - Solid black fill

This produces the classic via appearance: a filled hole surrounded by a copper annular ring.

### Pad Shapes

Pad rendering dispatches on `PadShape` (from `shape_top` field):

| PadShape | Rendering | Notes |
|---|---|---|
| `Round` | `draw_ellipse(loc, w/2, h/2, pen, solid_fill)` | Circular when w == h |
| `Rectangular` | `push_transform(Rotate)` + `draw_rect` + `pop_transform` | Rotated about pad center |
| `Octagonal` | `draw_polygon(8 points)` | See octagon geometry below |
| `RoundedRectangular` | `push_transform(Rotate)` + `draw_rounded_rect` + `pop_transform` | Corner radius = 25% heuristic |
| Other / Unknown | `draw_rect` fallback | No rotation applied |

Pad dimensions come from `size_top: CoordPoint` where `.x` is width and `.y` is height.
Half-widths are used for offset from center:
```rust
let w = c_to_f(p.size_top.x) / 2.0;
let h = c_to_f(p.size_top.y) / 2.0;
```

### Octagonal Pad Geometry

The octagon is generated by cutting corners from a rectangle at 45°. The cut factor
is `0.2929` (= `1 - 1/√2 ≈ 0.2929`), which produces regular 45° chamfers:

```rust
fn octagon_points(center: DrawPoint, w: f64, h: f64) -> [DrawPoint; 8] {
    let hw = w / 2.0;
    let hh = h / 2.0;
    let cut = 0.2929;       // 1 - cos(45°) = 1 - 1/√2
    let cx = hw * cut;
    let cy = hh * cut;
    // Points go clockwise from bottom-left:
    [
        (center.0 - hw + cx, center.1 - hh),       // bottom edge, left
        (center.0 + hw - cx, center.1 - hh),       // bottom edge, right
        (center.0 + hw,      center.1 - hh + cy),  // right edge, bottom
        (center.0 + hw,      center.1 + hh - cy),  // right edge, top
        (center.0 + hw - cx, center.1 + hh),       // top edge, right
        (center.0 - hw + cx, center.1 + hh),       // top edge, left
        (center.0 - hw,      center.1 + hh - cy),  // left edge, top
        (center.0 - hw,      center.1 - hh + cy),  // left edge, bottom
    ]
}
```

For a square pad, this produces a regular octagon. For rectangular pads, the chamfers
are proportional to each dimension.

### Rounded Rectangular Pad Corner Radius

Current implementation uses a 25% heuristic:
```rust
rx = w * 0.25    // corner radius X = 25% of half-width
ry = h * 0.25    // corner radius Y = 25% of half-height
```

**Altium's actual behavior**: Each pad stores a `CornerRadiusPercentage` field
(typically 0-100) that specifies the corner radius as a percentage of the smaller
dimension. The current 25% is a reasonable default but doesn't match per-pad settings.

### Fill Rotation

Fills apply rotation about `corner1` (not center):
```rust
push_transform(Rotate { degrees: f.rotation, origin: to_dp(f.corner1) })
draw_rect(corner1, corner2, pen, brush)
pop_transform()
```

This matches Altium's behavior where fill rotation is about the first corner.

### Region Rendering

Regions are rendered as simple filled polygons using their `outline` vertex list.
Holes (cutouts) in regions are not currently rendered — Altium regions can have
multiple contours (outer boundary + inner holes) but we only draw the outer outline.

### ComponentBody Rendering

Component bodies are the 3D model outlines projected onto the 2D view. They render
as unfilled polygons (outline only) since the actual component graphics come from
the constituent pads, tracks, etc.

## Altium's PCB Rendering Pipeline (Reference)

From reverse-engineering `Advpcb.dll`:

### PCPainterClass

The main PCB painting class in Delphi. Key characteristics:

1. **Layer-ordered rendering**: Primitives are painted layer by layer, bottom to top.
   This ensures correct visual stacking (e.g., copper over substrate, solder mask
   over copper).

2. **Per-type VMT dispatch**: `PCPainterClass` has virtual methods per primitive type:
   - `PaintTrack`, `PaintArc`, `PaintVia`, `PaintPad`, `PaintFill`
   - `PaintRegion`, `PaintText`, `PaintComponentBody`
   - Each reads the primitive's `TObjectId` to dispatch.

3. **DRC visualization**: The painter can overlay Design Rule Check violations
   (clearance rings, keep-out zones) as a rendering mode.

### GraphiteView.dll

Altium's custom high-performance PCB renderer:

- Separate DLL loaded for the interactive PCB editor view
- Likely uses GPU acceleration (OpenGL/DirectX)
- Handles real-time pan/zoom with level-of-detail rendering
- Not used for print/export — those go through the standard 2D paint path

### Layer System

Altium's PCB layer system (`V6Layer` enum) affects rendering:

| Layer category | Examples | Typical color |
|---|---|---|
| Signal layers | `TopLayer`, `BottomLayer`, `Mid1`-`Mid30` | Red, Blue, varied |
| Plane layers | `InternalPlane1`-`InternalPlane16` | Brown variants |
| Mechanical | `Mechanical1`-`Mechanical32` | Yellow/purple |
| Silkscreen | `TopOverlay`, `BottomOverlay` | White, Yellow |
| Solder mask | `TopSolderMask`, `BottomSolderMask` | Purple |
| Paste | `TopPaste`, `BottomPaste` | Gray |
| Keep-out | `KeepOutLayer` | Magenta |
| Multi-layer | `MultiLayer` | Gray (displayed on all layers) |

The actual colors are stored in the PCB document's layer configuration and are
user-customizable. There's no single "correct" color for any layer.

### Pad Stack Rendering

In Altium, pads are actually "pad stacks" with potentially different shapes per layer:
- `shape_top` / `size_top` — Top layer shape
- `shape_mid` / `size_mid` — Mid layers shape
- `shape_bot` / `size_bot` — Bottom layer shape
- `hole_size` — Drill hole diameter

Our renderer only uses `shape_top` / `size_top` since we render all layers as one
flat view. A proper multi-layer renderer would need to select the appropriate
shape/size for the layer being drawn.

## Known Limitations

1. **Monochrome output** — Everything renders in black; no layer color support
2. **No layer filtering** — All primitives on all layers are drawn
3. **No pad stack layers** — Only top layer pad shape used
4. **No region holes** — Multi-contour regions render only outer outline
5. **Fixed corner radius** — RoundedRectangular pads use 25% instead of per-pad percentage
6. **No net coloring** — Pads/tracks on same net aren't color-grouped
7. **No DRC overlay** — No clearance or rule violation visualization
8. **No board outline** — Board edge (mechanical layer) isn't specially handled
