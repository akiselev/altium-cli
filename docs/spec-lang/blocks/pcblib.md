# PCB Library (`.pcblib-spec`)

A `.pcblib-spec` file describes the footprints (land patterns) in an Altium PCB
library (`PcbLib`). Its top-level blocks are `footprint` declarations (plus
optional `import` directives and `let` bindings). Each `footprint` compiles to
one `PcbLib` footprint: its pads and graphic primitives, plus metadata.

**Related pages:** [Blocks overview](../language/blocks-overview.md) ·
[Types and values](../language/types-and-values.md) ·
[SchLib blocks](schlib.md) · [Placement](placement.md) ·
[Annotations](../language/annotations.md) ·
[Altium mapping reference](../reference/altium-mapping.md)

## `footprint`

The top-level block of a PCB library. The block name becomes the footprint's
display name.

```hcl
[binding =] footprint NAME {
    description: "..."
    height: <dim>
    pattern: "..."
    # pad / row / column / grid / graphic blocks
}
```

The block name (`NAME`) may be a bare identifier, a quoted string, or an
integer. An optional `#[annotation(...)]` attribute may precede the block (see
[Annotations](../language/annotations.md)).

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `description` | string | No | Footprint description. Compiles to `FootprintSpec.description`. |
| `height` | dim | No | 3D body / component height. Compiles to `FootprintSpec.height`. |
| `pattern` | string | No | Footprint pattern name. Defaults to the display name on apply. |

Pads and graphics come from the child blocks below (`pad`, `row`/`column`,
`grid`, and graphic blocks).

**Maps to Altium:** one entry in the `PcbLib` footprint list.
`compile_footprint` (in `src/compiler.rs`) builds a `FootprintSpec`;
`footprint_from_pcblib_spec` (in `src/executor.rs`) produces an `api::Footprint`
with `display_name`, `description`, `pattern` (defaults to `display_name`),
`height` (defaults to `0`), pads, and graphics. Existing footprints are merged
additively.

### Example

```hcl
footprint "R_0603" {
    description: "SMD resistor 0603"
    pad 1 {
        at: (0mil, 0mil)
        shape: "rectangular"
        x_size: 60mil
        y_size: 80mil
        layer: "TopLayer"
    }
    pad 2 {
        at: (100mil, 0mil)
        shape: "rectangular"
        x_size: 60mil
        y_size: 80mil
        layer: "TopLayer"
    }
}
```

## `pad`

Declares a single pad. The block name is the pad designator. A `pad` block may
also override a single pad generated by a `row`/`column`/`grid` layout (matched
by name).

```hcl
[binding =] pad DESIGNATOR {
    at: (x, y)            # or x:/y:
    shape: "..."
    x_size: <dim>
    y_size: <dim>
    layer: "..."
    hole_size: <dim>
    # ... plating, mask, thermal relief, stack overrides
}
```

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `at` | tuple `(x, y)` | No | Pad center. Alternative to `x:`/`y:`. Defaults to `(0, 0)`. |
| `x`, `y` | dim | No | Individual coordinate components if `at` is not used. |
| `shape` | string | No | Pad shape (see values below). Defaults to `Rectangular` on apply. |
| `x_size` | dim | No | Pad width (top layer). Defaults to 60 mil on apply. |
| `y_size` | dim | No | Pad height (top layer). Defaults to 60 mil on apply. |
| `rotation` | float | No | Pad rotation in degrees. Defaults to `0`. |
| `hole_size` | dim | No | Drill hole diameter (0 ⇒ SMD pad). |
| `is_plated` | bool | No | Plated-through hole. Defaults to `true` on apply. |
| `layer` | string | No | Layer name or `copper(N)`. Defaults to `MultiLayer` on apply. |
| `pad_mode` | string | No | Pad stack mode: `simple`, `local_stack`/`localstack`, `external_stack`/`externalstack`. |
| `solder_mask_expansion` | dim | No | Solder-mask expansion. |
| `paste_mask_expansion` | dim | No | Paste-mask expansion. |
| `plane_connection` | string | No | Plane connection style (`PlaneConnectionStyle`). |
| `relief_conductor_width` | dim | No | Thermal relief conductor width. |
| `relief_entries` | integer | No | Number of thermal relief spokes. Defaults to `4` on apply. |
| `relief_air_gap` | dim | No | Thermal relief air gap. |
| `mid_shape` / `mid_x_size` / `mid_y_size` | string / dim | No | Mid-layer stack overrides (LocalStack/ExternalStack pads). |
| `bot_shape` / `bot_x_size` / `bot_y_size` | string / dim | No | Bottom-layer stack overrides. |
| `hole_shape` | string | No | Hole shape: `round`, `square`, `slot`. |
| `slot_size` | dim | No | Slot length for slotted holes. |

Accepted `shape` values (case-insensitive, from `parse_pad_shape`):
`no_shape`/`none`, `round`/`circle`, `rectangular`/`rect`/`square`,
`octagonal`/`octagon`, `arc`, `terminator`, `round_rect`/`roundrect`,
`rotated_rect`/`rotatedrect`, `rounded_rectangular`/`roundedrectangular`,
`custom`.

The `layer` value accepts a copper-position helper `copper(N)` (resolved against
a board stack at execution time) or any named layer (`"TopLayer"`,
`"MultiLayer"`, …).

**Maps to Altium:** `compile_pad` → `PadSpec`; `pad_from_pcblib_spec` in
`src/executor.rs` → `api::Pad`. Properties map directly: `at` → `location`,
`shape`, `x_size`/`y_size`, `rotation`, `hole_size`, `is_plated`, `layer`
(resolved via `resolve_layer_spec`), `pad_mode`, the two mask expansions, the
thermal-relief fields, and the mid/bot/hole stack overrides → the pad's
`PadStack` (`pad_stack_from_spec`).

### Example

```hcl
footprint "TQFP_THERMAL" {
    pad "EP" {
        at: (0mil, 0mil)
        shape: "rectangular"
        x_size: 200mil
        y_size: 200mil
        layer: "TopLayer"
        plane_connection: "direct"
    }
    pad 1 {
        at: (-150mil, 100mil)
        shape: "round"
        x_size: 30mil
        y_size: 30mil
        hole_size: 16mil
        layer: "MultiLayer"
    }
}
```

> Coordinates and sizes use the dimension grammar in
> [Types and values](../language/types-and-values.md). `60mil` is `600_000`
> internal units.

## `row` / `column` — linear pad arrays

Generates a line of evenly spaced pads. `column` is a parser alias for `row`
(both compile through `expand_row` in `src/compiler.rs`).

```hcl
row {
    at: (x, y)            # absolute start coordinate, OR  on: $body.edge
    pitch: <dim>
    count: <int>
    start: <int>
    direction: "right"    # absolute: up/down/left/right
    skip: [N, ...]
    pad: { shape: "...", x_size: <dim>, y_size: <dim>, ... }
}
```

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `count` | integer | No | Number of pad positions. Defaults to `1`. |
| `start` | integer | No | First pad number. Defaults to `1`. Pads are named `start`, `start+1`, … |
| `pitch` | dim | No | Center-to-center spacing. Defaults to `0`. |
| `at` | tuple | No (absolute mode) | Coordinate of the first pad. |
| `direction` | string | No | Absolute mode: `up`/`down`/`left`/`right` (default `right`). |
| `on` | `$binding.edge` | No (anchor mode) | Anchor the row to a box-graphic edge (`left`/`right`/`top`/`bottom`). |
| `at` (anchor mode) | string | No | Anchor position along the edge: `start`/`center`/`end` (default `center`). |
| `skip` | array of int/string | No | Pad names to skip (the counter still advances; e.g. `skip: [3]` yields `1,2,4,5,6`). |
| `pad` | object | No | Template applied to every generated pad — accepts the full `pad` property set above. |

In **absolute mode** (`at:` is a coordinate) only the directions
`up`/`down`/`left`/`right` are valid. In **anchor mode** (`on: $binding.edge`),
the direction follows the edge and the `at:` string selects the alignment;
`up`/`down`/`left`/`right` are rejected.

**Maps to Altium:** each generated pad is a `PadSpec` (via `pad_from_template`),
applied identically to an explicit `pad`. A same-named explicit `pad` block
overrides the generated pad's properties in place (position is kept from the
layout) — see `merge_pad_override_from_props`.

### Example

```hcl
footprint "CONN_4" {
    row {
        at: (0mil, 0mil)
        pitch: 100mil
        count: 4
        start: 1
        direction: "right"
        pad: { shape: "round", x_size: 60mil, y_size: 60mil }
    }
    # Override only pad 2 to a rectangular anchor pad.
    pad 2 { shape: "rectangular", x_size: 80mil, y_size: 30mil }
}
```

## `grid` — 2D pad arrays (BGA/LGA)

Generates a rectangular grid of pads, optionally with BGA-style alphanumeric
naming and perimeter-only population (`expand_grid` in `src/compiler.rs`).

```hcl
grid {
    origin: (x, y)
    rows: <int>
    cols: <int>
    pitch: <dim>          # or pitch_x / pitch_y
    naming: "numeric"     # or "alphanumeric"
    perimeter_only: <bool>
    skip: ["A2", ...]
    pad: { shape: "...", ... }
}
```

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `rows` | integer | No | Row count. Defaults to `1`. |
| `cols` | integer | No | Column count. Defaults to `1`. |
| `pitch` | dim | No | Symmetric pitch. Defaults to `0`. |
| `pitch_x` / `pitch_y` | dim | No | Asymmetric pitch; each defaults to `pitch`. |
| `origin` | tuple | No | Grid center. Defaults to `(0, 0)`. Row 0 is the top row. |
| `naming` | string | No | `numeric` (1,2,3,… row-major) or `alphanumeric` (A1, A2, …). Defaults to `numeric`. |
| `perimeter_only` | bool | No | Populate only the outer ring of pads. Defaults to `false`. |
| `skip` | array | No | Pad names to omit (e.g. `["A2", "B1"]`). |
| `pad` | object | No | Pad template applied to every generated pad. |

Alphanumeric row letters follow BGA convention: `A`–`Z` skipping `I, O, Q, S,
X, Z`, then `AA`, `AB`, … (`bga_row_letter`).

**Maps to Altium:** each grid cell becomes a `PadSpec` (`pad_from_template`),
applied the same as explicit pads. Same-named explicit `pad` blocks override
generated pads.

### Example

```hcl
footprint "BGA_2x3" {
    grid {
        origin: (0mil, 0mil)
        rows: 2
        cols: 3
        pitch: 100mil
        naming: "alphanumeric"
        pad: { shape: "round", x_size: 40mil, y_size: 40mil }
    }
    # Generates pads A1 A2 A3 B1 B2 B3
}
```

## `graphic` primitives

Inside a `footprint` you can draw silkscreen, copper, courtyard, and 3D body
geometry using graphic blocks. The recognized PCB graphic types
(`PCB_GRAPHIC_TYPES` in `src/ast.rs`) are: `track`, `arc`, `fill`, `region`,
`text`, `via`, `component_body`, `line`, `polyline`.

```hcl
[binding =] GRAPHIC_TYPE {
    layer: "..."
    width: <dim>
    from: (x, y)
    to: (x, y)
    # type-specific properties
}
```

The full property set is defined by `PcbGraphicProperties` in `src/model.rs`:

| Name | Type | Description |
| --- | --- | --- |
| `layer` | string | Layer name or `copper(N)`. |
| `width` | dim | Line/track width. |
| `from`, `to` | tuple | Endpoints (track, line). |
| `corner1`, `corner2` | tuple | Fill rectangle corners. |
| `center` | tuple | Arc center. |
| `radius` | dim | Arc radius. |
| `start_angle`, `end_angle` | float | Arc sweep (degrees). |
| `points` | array of tuple | Vertex list (polyline). |
| `outline` | contour | Region / component-body contour (line and arc segments; `ContourSegmentSpec`). |
| `text` | string | Text content. |
| `at` | tuple | Text position. |
| `rotation` | float | Text/primitive rotation. |
| `hole_size` | dim | Via hole size. |
| `diameter` | dim | Via diameter. |
| `is_solid` | bool | Solid fill flag. |
| `height` | dim | Component-body height. |
| `model` | string | Component-body 3D model reference. |

**Maps to Altium:** `compile_pcb_graphic` → `PcbGraphicSpec`, applied as the
matching PCB primitive (track, arc, fill, region, text, via, component body).
Each graphic gets a unique ID `spec:{footprint}:{binding-or-type_index}`.

### Example

```hcl
footprint "R_0603" {
    silk = track {
        layer: "TopOverlay"
        width: 5mil
        from: (-50mil, 30mil)
        to: (50mil, 30mil)
    }
}
```

## Board / pad geometry (`PadGeometrySpec`)

`PadGeometrySpec` and the board-geometry types (`KeepoutSpec`,
`BoardLayerSpec`) defined in `src/model.rs` are **not** produced by
`.pcblib-spec` footprints. They belong to the PcbDoc domain: `PadGeometrySpec`
records the per-pad copper geometry of a *placed* component instance (designator,
position, shape, X/Y size, hole, layer, net, rotation) on a `PcbDocComponentSpec`.
See [PcbDoc blocks](pcbdoc.md). Pad geometry inside a library footprint is
expressed with the `pad`/`row`/`grid` blocks documented above, which compile to
`PadSpec`.

## Complete worked example — grid + row footprint

```hcl
#[annotation(id = "FPT00001A")]
footprint "QFN-16" {
    description: "16-lead QFN, 0.5 mm pitch"
    height: 35mil

    # Exposed thermal pad in the center.
    pad "EP" {
        at: (0mil, 0mil)
        shape: "rectangular"
        x_size: 100mil
        y_size: 100mil
        layer: "TopLayer"
        plane_connection: "direct"
    }

    # Four sides of perimeter pads via a grid (perimeter only),
    # overriding the corner with a row would also be possible.
    grid {
        origin: (0mil, 0mil)
        rows: 5
        cols: 5
        pitch: 50mil
        naming: "numeric"
        perimeter_only: true
        skip: [13]
        pad: { shape: "rounded_rectangular", x_size: 12mil, y_size: 24mil }
    }

    # Silkscreen outline.
    body_top = track {
        layer: "TopOverlay"
        width: 5mil
        from: (-75mil, 75mil)
        to: (75mil, 75mil)
    }
}
```

This compiles (`compile_footprint`) to one `FootprintSpec` whose pads come from
both the explicit `pad` blocks and the expanded `grid`, and applies
(`apply_spec_pcblib`) as a single `PcbLib` footprint.
