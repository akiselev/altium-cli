## Fidelity Assessment

**CONCERNING**: The parameter reordering is benign, but two distinct default-value omission issues affect 19 blocks total. The `SuppressAll=F` omission (14 blocks) and `ShowNetName=F` omission (5 blocks) represent cases where our serializer drops boolean `F` values that were explicitly stored in the original file. While Altium interprets the absence of these fields identically to `=F`, this is technically data loss.

## Impact on File Format Support

**What's working well:**
- Massive pin count (1,266+ pins with RECORD=2) all serialize correctly with all values preserved
- Complex pin fields including `%UTF8%SwapIDPart` with broken-bar (`|`) escaping are handled correctly
- `FileVersionInfo` base64-encoded gzip blob in RECORD=31 is preserved exactly
- Custom sheet settings (UseCustomSheet, ReferenceZonesOn, CustomXZones, etc.) are preserved
- No ERC marker `ErrorKindSetToSuppress` text strings are preserved correctly
- The 5 blocks of "changed size" are fully accounted for by the missing `ShowNetName=F` parameter, confirming no other data is lost

**What needs improvement:**
- Parameter serialization order does not match Altium's native order for RECORD=2, RECORD=17, RECORD=22, RECORD=27
- Font field ordering in RECORD=31 differs from original
- `Weight=0` is injected into /Additional HEADER when the original omitted it
- /Storage binary block size changes by -2,208 bytes

**Specific bugs revealed:**
- **Default value omission bug (SuppressAll=F)**: RECORD=22 (No ERC Marker) serializer drops `SuppressAll=F`. Same bug as file 18. Affects 14 blocks in this file.
- **Default value omission bug (ShowNetName=F)**: RECORD=17 (Power Object) serializer drops `ShowNetName=F` when Style=5. This is the only file in the batch where this occurs, suggesting it may be specific to `Style=5` power objects (which use a different display mode where the net name is hidden). 5 blocks affected.
- **Default value injection bug (Weight=0)**: The /Additional HEADER block gains `Weight=0` that was not in the original. The serializer should omit this when it equals the default.
